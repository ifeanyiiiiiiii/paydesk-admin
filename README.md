# PayDesk Admin

An open-source admin dashboard for a fictional payments platform: the operations console a fintech team uses to manage businesses, wallets, transactions, fees and admin access.

It's built to production standards with realistic generated data, so anyone can run it, read the code and try every feature. PayDesk isn't affiliated with any real company.

**Live demo:** https://paydesk-admin-omega.vercel.app

> 🚧 **In active development.** See the [roadmap](#roadmap) for progress.

## Tech stack

- **Framework:** Next.js (App Router), React, TypeScript
- **Styling:** Tailwind CSS, shadcn/ui
- **Auth:** encrypted cookie sessions (iron-session), role-based permissions
- **Data:** Zod for validating URL params; a seeded generator for realistic demo data
- **Charts:** Recharts
- **Client data:** TanStack Query (optimistic updates with rollback), React Hook Form + Zod forms
- **Testing:** Vitest
- **CI:** GitHub Actions (lint, type check, tests, build on every push)

More will be added as features land: Playwright end-to-end tests.

## Design decisions

### Money is always integer kobo

Every amount is stored and passed around as a whole number of kobo (₦1 = 100 kobo) using a branded `Kobo` type. Floats are never used for money, and conversion to naira happens only when displaying. This prevents floating-point errors (`0.1 + 0.2 !== 0.3`) and unit mix-ups that make dashboards show figures 100× too large. See [`src/lib/money.ts`](src/lib/money.ts) and its tests.

### Authentication and permissions

The demo has three fictional accounts, one per role. Pick one on the login page, no password needed.

| Role | Can do |
|---|---|
| Super admin | Everything, including fee rules and admin accounts |
| Operations | Day-to-day operations: freeze wallets, approve withdrawals, export transactions |
| Viewer | Read-only access to transactions, businesses and wallets |

How it works:

- **Session:** an encrypted, httpOnly cookie that holds only the user ID and expires after 8 hours. See [`src/lib/auth/session.ts`](src/lib/auth/session.ts).
- **Permissions, not roles, in checks:** code asks `can(role, "wallets:freeze")` rather than "is this a super admin?", so a role's abilities live in one tested map. See [`src/lib/auth/permissions.ts`](src/lib/auth/permissions.ts).
- **Two layers of checks:** [`src/proxy.ts`](src/proxy.ts) quickly sends visitors without a session cookie to the login page, and the data access layer ([`src/lib/auth/dal.ts`](src/lib/auth/dal.ts)) does the real check on the server for every protected page. Hiding a sidebar link is never the only thing keeping someone out.
- **Safe redirects:** after login you return to the page you asked for, but only same-site paths are allowed, so a crafted link can't send you to another site.

### Realistic, reproducible demo data

PayDesk ships with 5,000 fictional transactions across 24 businesses, generated by a small seeded random generator rather than `Math.random()`. Every server, test run and deploy sees exactly the same data, so tests can assert on it and pages render the same everywhere. Fees are calculated with the same `calculateFee` used everywhere else, and failed payments are never charged. See [`src/lib/data/seed.ts`](src/lib/data/seed.ts).

### Filters live in the URL

Search, filters and pagination on the transactions page are stored in the URL (for example `/transactions?q=kola&status=failed&page=2`), so any view can be bookmarked, shared or reloaded, and Back and Forward work. The server validates every param with Zod and falls back to defaults instead of erroring, so a hand-edited link still opens a working page. Search is debounced, so the server is queried when typing pauses, not on every keystroke.

The details drawer works the same way: clicking a row adds `?txn=txn_00931` to the URL, so a link to one specific transaction can be shared, and Back closes it. Dates are shown and filtered in Lagos time, so a payment displayed as 21 Oct never matches a filter that ends on 20 Oct.

### Safe CSV export

Operations and super admins can export every transaction matching the current filters (all pages, not just the visible one). The export endpoint checks permission itself, so a viewer who opens the URL directly gets a 403, not data. Values that look like spreadsheet formulas (`=`, `+`, `-`, `@`) are escaped to prevent CSV injection, amounts are written as exact decimals built from integer kobo, and responses are marked `no-store` because they contain customer data. See [`src/lib/csv.ts`](src/lib/csv.ts).

### An overview you can click through

The overview shows headline numbers (volume, transaction count, success rate, fees) against the previous period, daily collections and payouts, the status mix and the top businesses for the last 7, 30 or 90 days. Every part is a way into the data: click a day on the chart, a status or a business, and you land on the transactions page filtered to exactly that slice.

The charts follow a few rules: one shared axis (never two y-scales), colours checked for colourblind separation and contrast in both light and dark mode, status colours always paired with an icon and label, straight lines for daily totals, and a "Show as table" view with the same data for screen readers and exact values. The numbers come from a pure, tested `computeOverview` function. See [`src/lib/analytics/overview.ts`](src/lib/analytics/overview.ts).

### Wallets: optimistic updates that roll back

Freezing or unfreezing a wallet updates the list instantly. If the server refuses (no permission, already frozen, a network failure), TanStack Query restores exactly what was there before and an error message explains why. Freezing needs a reason, checked by the same Zod schema in the browser form and in the API, so they can't disagree. See [`src/components/wallets/use-wallets.ts`](src/components/wallets/use-wallets.ts).

### Every visitor gets their own sandbox

PayDesk is a public demo, so one visitor freezing a wallet shouldn't change it for everyone. Each visitor's changes are stored in their own encrypted, httpOnly cookie and layered on top of the shared demo data. Changes survive a reload, nobody can affect anyone else, and it works on serverless hosting where server memory isn't shared between requests. See [`src/lib/sandbox/sandbox.ts`](src/lib/sandbox/sandbox.ts).

### Withdrawals can't pay twice

Moving money is treated differently from freezing a wallet:

- **Not optimistic:** the balance only changes once the server confirms, because money shouldn't look sent before it is.
- **Idempotency key:** each attempt carries a unique key. If the response gets lost and the user retries, the server recognises the key and returns the original result instead of paying again.
- **The server decides:** the balance, freeze status, fee and account holder's name are all worked out on the server. The client only says what it wants, so a tampered request can't change the fee or overdraw a wallet.
- **Review first:** a live fee quote while typing, an account name lookup, then a confirmation step, because withdrawals can't be undone.

See [`src/lib/wallets/service.ts`](src/lib/wallets/service.ts) and [`src/lib/wallets/withdrawals.ts`](src/lib/wallets/withdrawals.ts).

### Fee rules change what gets charged

Fees are rules, not numbers stored on a page: a default per channel, plus custom rates agreed with individual businesses. The same `calculateFee` powers the form's preview and the server's charge.

- **The approved fee is the fee charged:** the review screen sends the fee the admin saw. If a rule changed in the meantime, the server refuses and nothing moves, and the dialog shows the new total to approve instead of quietly charging a different amount.
- **See the impact before saving:** the form compares the rule with today's on sample payments and on the last 30 days of real transactions. A change to a default leaves out businesses on a custom rate, because it wouldn't affect them.
- **The past stays the past:** a transaction stores the fee it was charged, so changing a rule never rewrites history.
- **Exact percentages:** "1.15%" is parsed from its digits into 115 basis points. In floating point, `1.15 * 100` is `114.99999999999999`.
- **Negotiated rates are need-to-know:** viewers can't open the fees page, and fee rules are also stripped from the wallet data sent to their browser, since the page isn't the only way to read an API.

See [`src/lib/fees/fees.ts`](src/lib/fees/fees.ts).

### APIs answer with status codes

Routes under `/api` never redirect to the login page. They return JSON with 401 (not signed in), 403 (not allowed), 400 (invalid input), 404 or 409 (a change that doesn't make sense, like freezing a frozen wallet), so the client can react properly.

## Running locally

Requires Node.js 22.

```bash
npm install
cp .env.example .env.local   # then set SESSION_PASSWORD (32+ characters)
npm run dev
```

Open http://localhost:3000.

| Command | What it does |
|---|---|
| `npm run dev` | Start the dev server |
| `npm test` | Run unit tests |
| `npm run typecheck` | Type-check the project |
| `npm run lint` | Lint the project |
| `npm run build` | Production build |
